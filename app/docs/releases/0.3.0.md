# Auto Research Agent 0.3.0

[English](0.3.0.md) · [简体中文](0.3.0.zh-CN.md)

The application now lives in `app/`. The public `example/` and newly created research folders sit beside it. Run `./start`, open the printed local URL, and use **+** next to the existing selector to create a research folder. The selector switches data without restarting; its last selection persists.

## Compatibility boundary

This minor release changes source checkout paths and developer commands. Package metadata is now `app/pyproject.toml`, the environment is `app/.venv/`, and internal commands run from `app/`. Root `make` targets continue forwarding to the application. Wheel installations still provide the CLI only and use the current directory as the workspace; a fresh mock seeds `example/` directly. Both CLI and dashboard server accept an explicit `--workspace`.

Existing `projects/<name>/` remains supported in place, with legacy precedence over duplicate sibling names. Invalid legacy projects cannot silently fall back to another folder. Existing data, checkpoint identities and artifact formats are not migrated. No relocation tool is supplied because moving checkpoints is not a safe generic file operation. Read the [upgrade and rollback guide](../user/workspace-upgrade.md) before updating. Old 0.2.x cannot discover new sibling research folders.

## Validation and limits

Acceptance covers first start, two-project creation/save/switch/restart, flat and legacy Mock workflows, legacy checkpoint/resume, CLI, wheel, privacy allowlists and both browser engines. Provider responses in workflow tests come from a loopback fixture; no paid model or cloud bot is used. A historical regression generates a genuine v0.2.2 run with that fixture and resumes it in its original path. Historical test checkout requires the v0.2.2 tag (CI fetches history).

No research capabilities, provider policies or UI design were changed. Old unused local environments/directories are not automatically deleted. Windows users can use `make ui` with a compatible shell or run `python -m ui.server` from the installed `app/` environment; the `start` entry point is a Bash launcher. Release testing covers macOS locally and Linux CI, not native Windows.

### Minimal legacy-example compatibility file

`projects/example/task.md` remains tracked so a real Git upgrade cannot delete the task underneath ignored old Runs, Memory or Checkpoints. New installations select top-level `example/` when this old directory contains only the untouched public task file and the top-level example has a readable task. Any old research file or customized legacy task keeps legacy precedence. This one-file compatibility directory is intentional; it is not automatically removed.
