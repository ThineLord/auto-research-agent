# Auto Research Agent 0.3.1

[English](0.3.1.md) · [简体中文](0.3.1.zh-CN.md)

This patch covers PRs #27 through #35 since v0.3.0. It fixes how the CLI and dashboard share research state and how source installations select Python.

## Changes

- The dashboard tracks active CLI runs on macOS and Linux, and a stop request applies only to the selected run. A failed startup or late stop cannot interrupt the next run. Existing manual stop files remain supported.
- The dashboard refreshes outputs, downloads and comparisons after a short external run finishes. Missing or blocked outputs have an explanation. Failed scores are excluded from comparisons and trends, while valid zeros and historical finite negative scores remain usable.
- Repeated literature surveys skip generated reports, including when the output location changes. Source paths distinguish similarly named drafts in flat and legacy workspaces.
- Recovery reports unusable checkpoints before provider checks and preserves the project and settings in the recovery command. For an interrupted mock, start a new offline mock. Empty project names are rejected.
- The launcher resolves relative workspaces from the caller’s directory. Make executes targets even when a project has the same name. Installation chooses Python 3.10+ and checks the selected environment and pip destination before installing. The launcher uses that environment for execution.

## Dependency security

Use Python 3.11 or newer for a new installation. Source installs through Make and installs using the release constraints select Pillow 13 on that interpreter. Python 3.10 stays compatible with existing workspaces, but its latest compatible Pillow release, 12.3.0, has outstanding upstream advisories. The application uses Pillow indirectly through Streamlit. Some advisories involve image formats, fonts or PDF processing. The application has no identified image-upload or Pillow processing entry point; other code sharing the environment may still use those paths. Use a newer interpreter before processing untrusted media. [Pillow 12.3.0 advisory](https://osv.dev/vulnerability/GHSA-fc9g-5qg7-mf45) · [Pillow 13.0.0 Python requirement](https://pypi.org/project/pillow/13.0.0/)

## Upgrade and rollback

Stop active runs and the dashboard, review local changes, and back up the private workspace. From a clean source checkout, fetch the tags, switch to `v0.3.1` and run `./start`. Developers can use `make install-dev`. Existing sibling and legacy project directories, checkpoints and run history stay in place. No data migration is required. To roll back from 0.3.1, stop the services and use the v0.3.0 source with its matching environment. Follow the [workspace guide](../user/workspace-upgrade.md) for upgrades from 0.2.x and for backup instructions.

An in-place pip upgrade can leave packages that newer dependencies no longer require. To reproduce the audited environment while retaining the previous one for rollback, choose an unused virtual-environment path and reuse it for startup. From the repository root:

```bash
make install-dev VENV="$HOME/.venvs/auto-research-agent-0.3.1" PYTHON=python3.13
VENV="$HOME/.venvs/auto-research-agent-0.3.1" ./start
```

## Verification and scope

The maintenance baseline passed 784 tests and 1,687 subtests on macOS. Linux CI covered Python 3.10 and 3.13, Chromium and WebKit. Acceptance included an isolated wheel install, real pip with a local sample package, and real CLI processes using offline mocks and a loopback HTTP fixture. These checks did not exercise hosted model providers or native Windows. The wheel provides the CLI. Use a source checkout for the dashboard.
