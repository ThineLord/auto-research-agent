# Auto Research Agent 0.3.1

[English](0.3.1.md) · [简体中文](0.3.1.zh-CN.md)

本补丁包含 v0.3.0 之后的 PR #27 至 #35，修复了 CLI 和仪表盘共享运行状态以及源码安装选择 Python 环境的问题。

## 主要变化

- macOS 和 Linux 上的仪表盘可以识别正在运行的 CLI。停止请求只对选中的运行生效；启动失败或收尾时收到停止请求，都不会误停下一次运行。手动停止文件继续可用。
- 外部 CLI 短任务结束后，仪表盘会更新产物、下载和运行比较。产物缺失或下载受阻时会显示原因。失败评分不再计入排名和趋势，有效零分与历史有限负分继续保留。
- 重复生成综述时会跳过已生成的报告，切换输出位置也能正确处理。同级项目和旧式工作区中的同名草稿都有可区分的来源路径。
- 恢复运行时先检查损坏的检查点，并在恢复命令中保留原项目和参数。中断的离线 mock 可以重新启动一次离线运行。创建项目时会拒绝空名称。
- 启动器从调用目录解析相对工作区路径。项目目录与 Make 目标同名时仍会执行命令。源码安装会选择 Python 3.10 或更高版本，检查所选虚拟环境及 pip 的实际安装目标，启动器也使用该环境。

## 依赖安全

新安装建议选用 Python 3.11 或更高版本，通过 Make 安装源码或使用发行版依赖约束安装时，这些解释器会选择 Pillow 13。Python 3.10 继续支持已有工作区，但与其兼容的最新 Pillow 12.3.0 仍有上游安全公告。应用通过 Streamlit 间接引入 Pillow。这些公告涉及图像格式、字体或 PDF 处理等路径。项目源码中未发现图像上传或调用 Pillow 的处理入口；同一环境中的其他程序仍可能调用相关功能。处理不可信媒体前请升级解释器。[Pillow 12.3.0 安全公告](https://osv.dev/vulnerability/GHSA-fc9g-5qg7-mf45) · [Pillow 13.0.0 的 Python 要求](https://pypi.org/project/pillow/13.0.0/)

## 升级与回滚

先停止运行和仪表盘，检查本地修改，备份私有工作区。在干净的源码检出获取标签并切换到 `v0.3.1` 后，运行 `./start`。开发安装可使用 `make install-dev`。原有同级项目、旧式项目目录、检查点和运行历史均可原位使用，无需迁移数据。回滚至 v0.3.0 时，先停止服务，再使用对应标签的源码和匹配的环境。从 0.2.x 升级及备份的具体步骤见[工作区指南](../user/workspace-upgrade.zh-CN.md)。

## 验证范围

本次维护基线在 macOS 通过 784 项测试与 1,687 项子测试。Linux CI 覆盖 Python 3.10、3.13、Chromium 和 WebKit。验收包括 wheel 隔离安装、使用真实 pip 安装本地样例包，以及通过离线 mock 和回环 HTTP 服务验证真实 CLI 进程。验证范围不包含托管模型服务或原生 Windows。wheel 提供 CLI，仪表盘使用源码检出。
