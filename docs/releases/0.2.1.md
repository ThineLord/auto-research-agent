## What changed

This maintenance release addresses all five P1–P2 findings from the 0.2.0 acceptance review.

| Priority | Improvement | Result |
| --- | --- | --- |
| P1 | Safe input editing | Save only edited fields; check revisions under the project lock. Background memory survives task-only saves. Conflicts preserve drafts and require an explicit choice. Applies to the web dashboard and legacy Streamlit editor. |
| P2 | Consistent Ollama endpoint | Discovery, startup validation and generation use the configured `ollama_base_url`; CLI defaults and `OLLAMA_HOST` cannot redirect discovery. |
| P2 | Trustworthy score handling | New Judge responses require complete weighted 25/25/20/20/10 rubric fields, bounded numeric points and a matching 0–100 total. Invalid responses fail scoring and cannot promote best output. Normal and diagnostic runs share rubric-first instructions and an arithmetic example to reduce inconsistent totals. |
| P2 | Browser regression coverage | Chromium and WebKit CI exercise real dashboard/CLI flows against an isolated loopback fixture: concurrent editing, focused and expanded editors during completion, stop/resume, outputs, analytics and language persistence. |
| P2 | Reproducibility metadata | Source installs, CI and wheel checks use release constraints. Run configs record actual application/Python/direct dependency versions and an optional Ollama digest; resumed sessions retain their own environment records. Unknown legacy provenance remains unknown. |

Implementation PRs: [#17](https://github.com/ThineLord/auto-research-agent/pull/17), [#18](https://github.com/ThineLord/auto-research-agent/pull/18), [#19](https://github.com/ThineLord/auto-research-agent/pull/19), [#20](https://github.com/ThineLord/auto-research-agent/pull/20), [#21](https://github.com/ThineLord/auto-research-agent/pull/21), [#23](https://github.com/ThineLord/auto-research-agent/pull/23), and [#24](https://github.com/ThineLord/auto-research-agent/pull/24). Codex implemented the changes; independent subagents reviewed and performed authorized merges.

Final browser acceptance also found and fixed a pre-Draft stop race: a stop arriving just after round creation now marks that attempt stopped, leaving a resumable checkpoint without fabricating a completed round. Deterministic round-1/round-2 regression tests fail on the old behavior and pass after the fix.

## Upgrade and compatibility

Stop active runs, preserve local edits and back up private work/configuration. Switch a clean checkout to `v0.2.1`, run `make install`, restart the dashboard and reload existing browser tabs. Reuse existing `config.yaml`; do not overwrite it with the example.

Runtime paths and existing checkpoints stay in place. Environment fields are additive; no research-data migration is required. Historical score readers remain compatible. New provider responses must satisfy the stricter scoring contract; a rejected response is a visible failed scoring step, not a fabricated score. Custom Judge prompts must follow the shared contract.

See [dependency constraints](../../requirements/README.md) for pinned setup. Source checkouts record the constraints fingerprint; wheel runs record null when that file is unavailable. Metadata does not guarantee deterministic model outputs. The wheel provides CLI functionality; the dashboard requires a source checkout.

## Validation and limits

Feature acceptance passed 656 Python tests and 1669 subtests, isolated wheel installation/mock execution, and four real-browser scenarios in each of Chromium and WebKit. Release acceptance additionally requires the final version's full checks, independent review and successful Python 3.10/3.13 plus browser CI on the PR and merged commit. The GitHub Release records final completed validation and the tested commit.

A synthetic local `llama3.1:8b` diagnostic completed all four stages with no agent errors and a valid total of 80 matching its rubric. A task-only dashboard save preserved the resulting memory byte-for-byte. An earlier `qwen3:8b` attempt timed out during Review; an earlier Llama response with total 90 versus rubric sum 80 was correctly rejected before the rubric-first prompt improvement. These are environment-specific acceptance observations, not model-quality guarantees.

Browser tests use synthetic inputs and a local fixture. WebKit is not native Safari certification. Real-provider availability and model output quality remain environment-dependent; the published release notes distinguish any live local diagnostic from fixture tests. Gemini was not called for this upgrade. No PyPI publication or private research assets are included.
